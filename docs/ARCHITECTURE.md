# Архитектура

## Жизненный цикл

ZombieBuddy обнаруживает `io.github.matveytomilov.pzblackbox.Main`, применяет пассивные `@Patch` и вызывает `main(String[])`. Shared Lua bootstrap проверяет наличие Java API при OnGameBoot/OnGameStart; OnTick обновляет контекст при наличии JAR. Повторный start идемпотентен. Загрузка/выгрузка мира не создаёт второй writer. После stop возможна новая сессия.

Каждая JVM имеет собственный PID, session_id и пару UTC/monotonic. BlackBox не подключается к другим процессам и не меняет launcher. Серверная запись возможна только при фактической загрузке агента в серверной JVM. Клиентские кадры не являются серверным TPS.

## Потоки

| Поток | Работа |
|---|---|
| Перехваченные игровые потоки | Начало/конец интервала, ограниченные счётчики, предложение события в неблокирующую очередь |
| GameThread / OnTick | Один снимок контекста, списка зомби и активных модов в секунду; скан зомби ограничен 2048 записями |
| PZBlackBox-sampler | MXBean, агрегация, ограниченная обработка ошибок и снимки Java-стеков |
| PZBlackBox-registry | Сканирование mod.info/Lua-источников и хеширование JAR отдельно от sampler |
| PZBlackBox-writer | JSONL, ротация, кольцевой буфер, триггерные окна, flush |
| PZBlackBox-export | Снимок/упаковка и фильтрация данных; может задержать writer, но не ожидающий игровой поток |

Ни один advice не пропускает исходный метод и не записывает его аргументы/результат. Исключения самой диагностики отключают соответствующий компонент. Ошибки игры продолжают штатную обработку. Опасные/непрошедшие трансформации нельзя включать в обычный пакет.

## Компоненты

CoreRecorder управляет сеансом, режимом и доступностью; FrameRecorder измеряет работу/интервалы; LuaRecorder ведёт вложенные границы; JavaRecorder управляет JFR; ErrorRecorder откладывает обработку ошибок; WorldRecorder считает загруженные сущности; StreamingRecorder различает этапы чанков; AssetRecorder наблюдает lookup и lifecycle; SystemRecorder читает MXBean; ContextRecorder читает состояние на игровом потоке; ModRegistry разделяет активный набор и объявленные Java-ресурсы; Exporter формирует безопасный ZIP.

## Ограничение ресурсов

Очередь: 8192 записи и оценочный бюджет 16 MiB. Кольцо: 16384 записи и 16 MiB, не более 30 секунд по источнику времени. Одна JSON-запись ограничена 128 KiB, строки — 8192 символами. Счётчики Lua ограничены 2048 ключами и overflow; метаданные closure — 4096 слабых ключей; asset-ключи — 2048; ожидающие lifecycle — 4096 слабых ключей; ключи дедупликации ошибок — 1024.

Ротация: 8 MiB. По умолчанию JSONL+trigger-бюджет сессии256MiB, JFR64MiB/10 минут. Документы метаданных отдельно ограничены8MiB; лимит одной строки JSONL остаётся128KiB. Очередь ошибок хранит256 ограниченных снимков (до32 stack frames), без сильных ссылок на Throwable/cause/suppressed; batch максимум128. Общий стартовый бюджет собственного каталога1GiB; резервируется место для ZIP, перед повторной упаковкой проверяется место с учётом старого архива и нового .part. Старые сеансы автоматически не удаляются. Эти бюджеты не являются измерением RSS процесса; внешние одновременные записи в каталог и отдельные JVM могут конкурировать за свободное место.

При штатном завершении writer дренируется с таймаутом, JFR сохраняется, экспорт получает ограниченное время. При `halt`, kill или сбое ОС последние события могут быть потеряны. Уже записанный JSONL остаётся читаемым; `session.json.complete` показывает штатное завершение writer, а не гарантию полноты всех игровых событий.
