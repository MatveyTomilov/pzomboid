# Ограничения кандидата

1. Реальный запуск B42 с BlackBox пока не выполнен. Меню, вход в мир, конкретные моды, транспорт и MP не объявлены проверенными. Общий игровой overhead 1–2% — цель, не результат измерения.
2. Поддерживается установленный ZombieBuddy 2.3.4/его 2.x API. Upstream 3.x поменял пакет аннотаций; `ZBVersionMax=2.9.9` намеренно предотвращает ложную совместимость. Нет зависимости от экспериментальных Watches/EventLog/PacketLog.
3. Host запускается отдельной JVM без автоматического переноса `-javaagent`. Без агента в ней серверные Java-метрики BLOCKED; запись на клиенте не заменяет серверную. Launcher не изменяется. Lua сообщает об отсутствии Java API.
4. Камера, прямые NPC timings, VRAM, GPU time, process RSS и точные очереди чанков не измеряются. Для них null/причина либо запись capabilities. Нет API-интеграций Viewpoint/A-Life/Tempo.
5. Наблюдаются границы LuaCaller, не внутренние Lua→Lua вызовы. Exclusive time ограничено наблюдаемыми дочерними вызовами. Код/функции с неразрешимым источником остаются unknown; совпадение пути не доказывает причинность.
6. Registry хранит активные Mod ID и точный jarPath ZombieBuddy. Объявленные JAR не приравниваются к загруженным. Есть отдельный ограниченный скан installed mod.info в обнаруженных по активным модам Steam Library и cachedir/mods, с версиями/хешами/флагом выбранного provider. Необнаруженные библиотеки могут отсутствовать; достижение лимита нельзя выдавать за отсутствие дублей. Относительный Lua-путь с несколькими кандидатами остаётся ambiguous.
7. Базовый AssetManager.startLoading может переопределяться; duration null при отсутствии пары. Lookup не различает все внутренние кеши, не измеряет VRAM. Загрузчики вне AssetManager/Texture не покрыты полностью.
8. Raw JFR остаётся локально и может содержать пути/имена потоков. Автоматический ZIP намеренно исключает его и оригинальные игровые логи, поскольку гарантировать очистку всех строк невозможно. Вместо raw JFR включается java-profile.jsonl: до20000 типизированных событий/4MiB, только безопасные числовые поля и Java method frames. Native JFR UTC и custom frame monotonic/UTC помечены отдельно. Сообщения ошибок и raw stack strings исключены; типы, хеши, счётчики и времена сохраняются. Пользователь не должен отправлять raw JFR автоматически.
9. Captures неполные при переполнении, лимите диска, остановке или аварии. При завершении до окончания 15 секунд после триггера будущих данных нет. Метрики пропусков/состояние завершения надо читать вместе с данными. Trigger и обычные каналы содержат одинаковые event_id — это не новые измерения.
10. Writer и exporter сериализуют доступ к файлам. Экспорт может временно заполнить очередь и вызвать drops, но игровой поток не должен ждать диска. Корректность на каждом игровом пути нуждается в smoke-тесте.
11. Нет криптографической подписи автора в кандидатном JAR. Это не поддельно подписанный релиз. Требуется обычное индивидуальное одобрение SHA-256 через установленную политику ZombieBuddy. Никакой allow-all не устанавливается.
