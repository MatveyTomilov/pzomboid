# Семантика измерений

Все длительности `_ns` используют `System.nanoTime()`. Временная отметка захватывается у источника события, не при записи на диск. `timestamp_utc` вычисляется по опорной паре JVM; отдельные `clock_anchor` позволяют заметить изменение настенных часов. `nanoTime` разных процессов несопоставим напрямую.

## Кадры

- `frame_work_ns`: вход–выход `GameWindow.frameStep`. Включает игровую логику, CPU-подготовку рендера, часть lighting/событий; не включает паузу ограничения FPS во внешнем цикле.
- `frame_interval_ns`: интервал между началами frameStep, включая pacing/ожидания. Первый интервал null.
- `logic_work_ns`: время `GameWindow.logic`.
- `render_submission_ns`: CPU-время `renderInternal`, не GPU и не весь RenderThread.
- `gpu_time_ns`: null, явного универсального измерения нет.

Сводки по секундам разделены по доступному состоянию world/world_paused/menu_or_loading/unknown. nearest-rank p95/p99 считаются только по наблюдаемым положительным интервалам. FPS = 1e9 / средний интервал. 1% low = 1e9 / среднее самых медленных ceil(n×0.01) интервалов. Это не переименование p99. При коротком окне малая выборка, при dropped/omitted выборка неполная. Пороговые счётчики — строго выше 33/50/100/200/500 ms. Ограничение FPS закономерно увеличивает интервал; само по себе это не дефект графики.

## Lua

Перехватываются 17 перегрузок пяти методов LuaCaller. Это границы Java→Lua, а не каждый Lua→Lua вызов. Массивные protectedCall-обёртки, делегирующие pcall того же closure, считаются один раз. Настоящие вложенные вызовы учитываются отдельно. Inclusive включает дочерние измеренные вызовы; exclusive вычитает только наблюдаемые дочерние границы, а не все внутренние функции Lua.

Детальный медленный вызов — от 2 ms; агрегаты включают быстрые вызовы. Корзины гистограммы в ns: ≤50000, ≤100000, ≤500000, ≤1000000, ≤2000000, ≤10000000, ≤50000000, больше. Событие берётся из вложенного контекста `zombie.Lua.Event.trigger`. Кеш метаданных читает prototype file/name/lines. Lua protected failures доступны для `pcall` с массивом результатов; все внутренние swallowed Lua errors этим механизмом не гарантируются.

## Мир и streaming

`loaded_zombies` — размер загруженного списка, не полная популяция карты. Nearby — радиус 50 квадратов; просматриваются максимум 2048 записей, флаг capped обязателен. Время IsoZombie.update — сумма перехваченных вызовов, не идентификаторы/число уникальных зомби и не отдельная стоимость NPC.

Этапы чанков: `WorldStreamer.DoChunkAlways` — оркестрация; `IsoChunk.LoadChunk` — загрузка/десериализация/возможный fallback; `loadInWorldStreamerThread` — подготовка; `doLoadGridsquare` — применение. Они могут быть вложенными. Суммировать их как независимые части кадра нельзя. Счётчик operations не является числом уникальных чанков. Очереди пока null.

## Ресурсы и JVM

Texture lookup измеряет выполнение поиска, не upload/работу GPU. Cache hit пока unknown: участвует несколько кешей. Lifecycle asset ограничен реально наблюдаемым start/completion; отсутствие start даёт null с причиной. Некоторые подклассы переопределяют startLoading — полнота покрытия не гарантируется.

CPU fraction = delta processCpuTime / delta monotonic / available processors, 0..1. Heap used/committed/max и non-heap — JVM-пулы, не RSS игры и не VRAM. GC time — накопительный MXBean счётчик в ms, не список всех stop-the-world пауз; их уточняет JFR. Java-стеки на триггере — мгновенный снимок с задержкой до sampler, не доказанная длительность метода. JFR execution samples статистические, не точные тайминги каждого Java-метода.
