# Приоритет: лаги пассажира с сохранением Viewpoint

Две проблемы могут ощущаться одинаково: низкий FPS/паузы кадров и рывки положения машины/камеры при нормальном FPS. Они могут существовать одновременно. В логах нет метки «водитель/пассажир» для каждого кадра, поэтому сейчас нельзя доказать одну окончательную причину. Сравнивать нужно на одинаковом маршруте, скорости, машине и погоде.

| Гипотеза | Подтверждено / ограничения | Безопасный ручной тест после согласования | Решение при подтверждении, Viewpoint сохраняется |
|---|---|---|---|

Viewpoint timings показывают многие паузы вне собственных passes. | Пассажир 1st/3rd/iso на известном коротком маршруте, одинаковая скорость. | Снизить детализацию/дальность и эффекты, исправить конкретное render-пересечение. |

Нет I/O trace или точной поездки. | Повтор того же маршрута затем короткий новый участок; сравнить оба клиента. | Уменьшить дальний 3D LOD/packRing, распределить build budget; компрессия/текстуры только после VRAM замера. |

## Роли

- Host за рулём: локальная физика/владение машиной может отличаться от случая, когда владелец машины — удалённый водитель. Это потенциальное объяснение, а не установленный механизм конкретного лага.
- Host пассажир / друг за рулём: одновременно local client+server CPU и возможная интерполяция удалённой машины; текущая главная жалоба.
- Друг пассажир / Host за рулём: на ПК друга нет JVM Host; если он тоже лагает, вероятнее общая симуляция/интерполяция/контент, чем конкуренция двух процессов только на Host.
- Если только у Host прыгает камера, а FPS нормален и машина у друга плавная, первым проверять camera-follow/interpolation. Если падает FPS обоим в новом районе, сначала streaming/render/ассеты. Если у обоих задерживаются все действия, смотреть Host ticks/network.

## Минимальный ручной план — около 3 минут

Только после отдельного разрешения на тест. Использовать копию мира/профиля, созданную пользователем при полностью выключенной игре; основной мир не загружать. Без стресс-тестов, орд, максимальной скорости и новых предметов. Изометрия — временный ориентир, не решение.

1. 15 секунд стоять, 15 секунд идти. Обоим записать FPS и точное время.
2. Один и тот же безопасный известный маршрут: Host водитель20s/друг пассажир, затем Host пассажир20s/друг водитель.
3. Host пассажир: 1st20s, 3rd20s, iso20s. Скорость, направление обзора и погодные эффекты одинаковы; порядок отметить.
4. Повторить участок20s, затем короткий ранее не загруженный участок20s. Зафиксировать, прыгает только камера или всё изображение/машина. Остаток времени — смена мест.

Расширенная матрица: обе водительские роли × три камеры × известный/новый маршрут плюс пешком; повторить каждый случай 20–30s, примерно10–15мин с переключениями. Не запускать автоматически.

## Метрики доступными средствами

- FPS: существующий игровой FPS-индикатор/Viewpoint диагностический вывод. Текущее F9 конфликтует с калибровкой ADS/скриншотом; не назначать/нажимать F9 ради предполагаемого overlay без проверки действующей функции. PZOpt Options/overlay использовать только если уже доступен и разрешено включение.
- Frametime: существующие slow-frame строки и frame cap averages доступны; полной percentile-series нет. Не вычислять p99 из выборки slow frames. Если overlay не выводит frametime, записать N/A.
- CPU: Task Manager, график по логическим процессорам; общий CPU может скрывать насыщение одного ядра. Per-processCPU/working set, общий commit и available RAM.
- GPU/VRAM: Task Manager вкладка GPU: dedicated/shared memory; существующий nvidia-smi read-only query. На Windows per-process VRAM может быть N/A. Не включать новые системные overlay/драйверные функции без согласования.
- Disk: Resource Monitor disk active time/response time и Hard Faults/sec. Hard fault не всегда чтение pagefile — может быть файл ассета.
- Ping: если существующий MP UI/scoreboard показывает ping, записать его. Иначе N/A; внешний ping до Steam relay не равен задержке игровых пакетов.
- Host: ALIFE-PERF и паузы/packet logs; TPS только если существующий инструмент реально его выводит. Новую отладку/JFR/GC flags не включать без согласования.

Сразу после теста сохранить console.txt, coop-console.txt, свежие Logs/DebugLog-server и DebugLog-client, logs.zip, а также короткую таблицу времени/роли/камеры/машины/скорости/маршрута/FPS и наблюдений. Логи друга особенно нужны: локальные FPS/ошибки нельзя восстановить по Host. Перед передачей обезличить, не отправлять save/* из logs.zip.
