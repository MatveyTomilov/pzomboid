## Без отключения модов

Сначала собрать замеры CPU по логическим процессорам, RAM commit/working set, VRAM, FPS и время проявления тряски. Сейчас игра выключена: свободные ресурсы в простое не доказывают отсутствие перегрузки в игре.

A-Life имеет измеренный долгий population job. Возможна настройка интервала offline обработки или распределение задачи по тикам, если это поддержано текущим кодом. Не менять Population_RatePercent, число NPC и сложность автоматически: это влияет на согласованный игровой процесс.

Ошибка More Car Features подтверждена в OnSpawnVehicleAdditionalFeatures.lua:789. Требуется безопасная для server JVM обработка замены script. Самостоятельное отключение мода или параметра No Vanilla Vehicles не предлагается как готовый фикс.

## Host, Java и память

PZ_Optimization действует и в Host. Логирует vehicleSmooth=interp, параллельную обработку анимаций/entities, physicsDefer и несколько worker pools. Контрольный Stock preset не исключает влияния самих подменённых классов; при необходимости отдельный тест с полным обратимым откатом loose files. Не удалять целиком папки zombie, media или org. Использовать verified installed-files.csv и резервную копию E:\PZ-Viewpoint-Recovery\pz-optimization-install-20261013-204106. Установленные файлы могли обновиться: перед откатом нужен новый точный список и копия текущих файлов. Все эти действия требуют согласования.

Клиент Xmx8GiB + Host UI7GiB не означают, что использованы все 15GiB. Нет peak heap/native/VRAM, GC pauses или paging measurements. Heap пока не увеличивать; не менять collector и не возвращать JVM flags вслепую.

Если подтверждена конкуренция CPU, проверить меньшее число worker threads по одной системе за раз. Риск — медленнее загрузка мира. Это обратимо, но требует согласования и перезапуска.

JFR/GC logging и профиль Lua позволят разделить паузы, но включение новых flags/профилировщиков требует разрешения. Дополнительные утилиты не устанавливать.

## Графика

- При измеренном GPU bottleneck: сначала дополнительные погодные эффекты/тени/LOD, затем разрешение 2560×1440. При паузах main thread снижение разрешения может не помочь.
- При VRAM pressure: уменьшение текстур машин/одежды или поддерживаемая компрессия через UI. Риск — качество и загрузка ассетов; параметры enum сначала прочитать в меню. Изменение клиентское, обратимо, не затрагивает сейв.
- Ограничение FPS 60 или 90 вместо 144 может оставить ресурс Host и улучшить ровность кадров. Оно не исправляет native errors или interpolation. Выбор согласовать; отменяется возвратом cap.
- Windows power plan, драйверы, pagefile, relay и сеть пока оставить: измеренных оснований для таких изменений нет.

## Возможные конфликты других модов

Первой дополнительной проверкой определить реальные jarPath из нового startup log ZombieBuddy. Локально сохранён Viewpoint 0.1.5a-hotfix, а Steam/Host содержит 0.1.6; локальные QOL/True Ballistics также имеют другой SHA-256. Не удалять эти копии и не считать их активными без доказательств. Если runtime выбирает старую копию, её исключение из поиска потребует отдельного согласования и сохранения архива. Это проверка загрузки, не повод откатывать Viewpoint.

True Cargo, 3D packs, кровь, расчленение и одежда увеличивают объём ассетов и потенциальные расходы рендера. Их вина не доказана. Сравнение визуальных опций допустимо после измерений, отключение контента — только по отдельному решению.

Precision/QOL/True Ballistics не объявлены сломанными по старым логам. Свежая ошибка Object → LootTargets.Target не найдена в сохранённых фрагментах, но это не доказательство всех игровых функций.

Утечка памяти не подтверждена. Нужен график heap/native/VRAM во времени, а не только отсутствие OOM. Не выдавать регулярные перезапуски за устранение утечки.
